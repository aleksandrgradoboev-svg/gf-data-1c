# gt-data-1c — сервер данных 1С (MCP). Спецификация

Статус: черновик на утверждение. Дата: 23.08.2026. Имя продукта предварительное.
Правообладатель: ООО Гринтех. Разработка с нуля («чистая комната»), решение Повелителя 23.08.2026.

## 1. Назначение и граница

Читает данные информационных баз 1С:Предприятие и отдаёт их агентам по протоколу MCP.
Только чтение. Метаданные и код конфигурации — не его дело (это `rlm-tools-bsl`),
документы и требования — тоже (вектор-база).

Обслуживает несколько информационных баз сразу — их список ведёт собственный реестр
сервера. Мультибаза — не опция, а исходное требование: вызов без явной базы уходит в базу
по умолчанию, и молчаливый уход не в ту базу выглядит как достоверный ответ.

## 2. Правовой режим — почему документ начинается с этого

Продукт пишется заново, чтобы права принадлежали ООО Гринтех целиком и вопрос
происхождения кода на аудите сделки не возникал вовсе.

**Что запрещено при разработке.** Исходники стороннего сервера `dat-tools-1c` / его донора
не открываются: ни для «подсмотреть решение», ни для сверки, ни для переноса тестов.
Заимствование строк, структуры пакетов, имён внутренних сущностей и текстов тестов исключено.

**Что разрешено как источник требований:**
- спецификация протокола MCP и официальный Go SDK (Apache-2.0);
- документация 1С: HTTP-сервисы, язык запросов, виртуальные таблицы регистров;
- **инструкции сервера, написанные нами** (текст `initialize` про мультибазу, `dat_probe`,
  отличие ресурсов виртуальной таблицы от ресурсов регистра) — наш собственный текст;
- внешнее поведение работающего сервера: запрос → ответ, без чтения его кода;
- наши стенды и их данные.

**Раскрытие (честность важнее удобства).** 23.08.2026 при лицензионном разборе автор
спецификации видел в стороннем репозитории: шапки трёх файлов, список переменных окружения,
маршрут HTTP-сервиса, строку URL по умолчанию, состав `go.mod`, имена файлов тестов.
Ничего из перечисленного не переносится: маршрут, имена переменных и раскладка файлов
проектируются здесь заново и намеренно иначе. Состав зависимостей — не объект охраны
(выбор библиотек диктуется протоколом), но и он пересматривается по существу.

## 3. Состав инструментов

Контракт каждого — вход, выход, отказ. Отказ никогда не маскируется под пустой результат:
первая строка ответа прямо говорит, что вызов не выполнен, и чем именно.

| Инструмент | Назначение | Ключевое требование |
|---|---|---|
| `probe` | жив ли канал по каждой базе | различает: веб-сервер погашен, расширение не установлено, отказ прав |
| `bases` | список известных баз | имя базы — параметр любого инструмента; незнакомое имя → отказ с перечнем известных |
| `base_info` | версия платформы, конфигурация, режим | версия расширения сверяется с версией сервера |
| `metadata` | состав метаданных | без фильтра — сводка по категориям; с фильтром — список объектов категории |
| `object` | реквизиты и структура объекта | типы называются явно (`CatalogRef.X`), а не прозой |
| `query` | произвольный запрос на языке 1С | перечисление полей вместо `*`; ссылка отдаётся с представлением И идентификатором |
| `query_check` | синтаксический разбор без исполнения | дешёвая проверка до дорогого вызова |
| `count` | число записей таблицы с отбором | не через `query` — отдельный инструмент, чтобы счёт не сочинялся |
| `register` | остатки и обороты регистра | имя виртуальной таблицы, границы периода, ресурсы (`ВНаличии` → `ВНаличииОстаток`) |
| `eventlog` | журнал регистрации | ограничение по числу записей, а не по размеру ответа |

Имена инструментов в реализации получают общий префикс продукта.

## 4. Архитектура

Проектируется от наших сценариев, а не от чужой раскладки:

- **транспорт** — официальный MCP Go SDK, stdio; ничего своего в протоколе;
- **реестр баз** — файл в профиле пользователя, путь по умолчанию без флагов; регистрация
  сводится к пути бинарника;
- **канал к базе** — HTTP-клиент к расширению внутри базы, учётные данные отдельно от URL
  (в URL они не хранятся и в журнал не попадают);
- **исполнители инструментов** — по одному модулю на предметную область (запросы, регистры,
  метаданные, журнал), общий слой валидации и форматирования;
- **диагностика** — отдельный модуль, отвечающий за различение видов отказа;
- **журнал** — файл в каталоге продукта, секреты в него не попадают никогда.

Один статически слинкованный бинарь Go, без рантайма и внешних зависимостей на машине агента.

## 5. Расширение 1С

Своё: собственный HTTP-сервис, собственный корневой URL, собственная роль доступа,
собственный формат ответов. Совместимости со сторонним маршрутом не требуется — это
новый продукт, а не замена по месту.

Требования: только чтение; версия отдаётся отдельным методом (по ней сервер понимает,
что расширение устарело); ошибка приходит структурой с причиной, а не пустым телом.

Цена изменений здесь выше, чем в сервере: пересборка `.cfe` и установка в каждую базу,
а для файловой базы — остановка веб-сервера на время операций с конфигурацией.

## 6. Приёмка

1. `probe` отвечает по обеим базам, три вида отказа воспроизводятся намеренно и различаются.
2. Набор контрольных вопросов по приёмочным базам даёт **те же числа**, что текущий канал:
   выручка за период, остатки на дату, число записей таблицы, срез журнала.
   Расхождение — блокер, а не «погрешность».
3. Отказ инструмента не выглядит как пустой результат — проверяется на погашенном
   веб-сервере и на базе без расширения.
4. Секреты отсутствуют в журнале и в ответах — проверяется грепом по журналу прогона.
5. `THIRD-PARTY-NOTICES.md` покрывает фактический список зависимостей сборки.

Переключение потребителей на новый канал — только после пунктов 1–5. До этого момента
текущий канал не гасится: без канала работа по данным не начинается.

## 7. Границы продукта — решённые, а не отложенные

Здесь то, чего продукт **не делает сознательно**. Список нужен ровно затем, чтобы
следующий заход не записал это в долги и не начал «доделывать».

- **Только русскоязычные конфигурации.** Имена метаданных и перевод в запросную нотацию
  написаны под русские префиксы. Англоязычных конфигураций у нас не будет — решение
  Повелителя 23.08.2026, это не критерий качества и не пробел.
- **Только чтение.** Запись не появится: запрос на изменение отклоняется до обращения
  к базе, и это свойство продукта, а не ограничение прав пользователя.
- **Код и метаданные конфигурации — не сюда.** Поиск по модулям, формы, подсистемы как
  предмет разработки закрывает `rlm-tools-bsl`; дублировать его здесь незачем.

Отдельно от этого — то, что просто **не сделано**. Часть этого списка закрыта 23.08.2026
(установщик с поддержкой серверных баз, срез регистров сведений, обороты по счетам, журнал
сервера, потолок размера ответа, сверка версий расширения и сервера), а осталось следующее:

- **доменная аутентификация** (NTLM/Kerberos) — сейчас только логин и пароль;
- **защищённое хранение паролей** реестра — они лежат открытым текстом в файле с правами 0600;
- **выгрузки крупнее тысячи строк** — ни пагинации, ни курсора, ни выгрузки в файл;
- **сетевой режим** — сервер живёт дочерним процессом одного агента;
- **снятие и обновление расширения** — ставим и перезаписываем, команды «удалить» нет.

Работа на прочих типовых конфигурациях **критерием не считается** (решение Повелителя
23.08.2026): у нас два стенда, и универсальный охват никому здесь не нужен. Риска в этом
и нет — расширение не привязано к расширяемой конфигурации, так что на новой базе от него
требуется только запуск установщика. Единственное, что при этом придётся дописать под
конкретную конфигурацию, — инструмент под её регистры расчёта, если понадобятся данные
зарплатного контура: сейчас такого инструмента нет.

Ни одно из этого не нужно нашим двум стендам и понадобится тому, кто станет продавать
продукт наружу.
