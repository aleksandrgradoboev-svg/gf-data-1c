# Контракт HTTP: сервер ↔ расширение в базе

Расширение публикует один HTTP-сервис. Сервер обращается к нему GET-ом, а запросы,
не помещающиеся в URL (текст запроса 1С), шлёт POST-ом с телом JSON.

Корневой URL задаётся при публикации базы и хранится в реестре целиком, поэтому
маршрут ниже — относительный.

## Общие правила

- Ответ всегда JSON, кодировка UTF-8.
- Успех: `200` и объект с данными.
- Неуспех **внутри** базы (негодный запрос, нет объекта, ошибка исполнения) — тоже `200`,
  но объект вида `{"ok":false,"error":"...","detail":"..."}`. Так сделано намеренно:
  HTTP-код в 1С легко перепутать с кодом веб-сервера, а серверу нужно отличать
  «база отказала осмысленно» от «канала нет».
- `404` не отдаётся никогда: этот код зарезервирован под «расширение не установлено»
  и опознаётся сервером именно так.
- Числа отдаются числами, даты — строкой ISO 8601, ссылки — объектом
  `{"представление":"…","тип":"CatalogRef.Номенклатура","идентификатор":"…"}`.
  Пустая ссылка — `null`, и это отличимо от пустой строки.

## Методы

| Метод | Verb | Параметры | Ответ |
|---|---|---|---|
| `version` | GET | — | `{"продукт","расширение","платформа"}` — проба живости, вызывается `probe` |
| `base` | GET | — | конфигурация, версия, поставщик, платформа, режим |
| `metadata` | GET | `filter` (опц.) | без фильтра — категории и количества; с фильтром — объекты категории |
| `object` | GET | `type`, `name` | реквизиты, табличные части, измерения, ресурсы, значения перечисления |
| `check` | POST | `{"query"}` | разбор текста запроса без исполнения |
| `query` | POST | `{"query","parameters","limit"}` | колонки и строки результата |
| `count` | POST | `{"table","where","parameters"}` | одно число |
| `register` | POST | `{"register","kind","period","start","end","dimensions","resources","where","parameters","limit"}` | строки итогов |
| `eventlog` | GET | `start`,`end`,`level`,`user`,`limit` | записи журнала регистрации |

## Права

Роль расширения даёт **только чтение**: просмотр данных и метаданных, чтение журнала
регистрации. Права на изменение не выдаются ни одному объекту — это ограничение самого
продукта, а не настройка пользователя.

## Версии

`version` возвращает версию расширения. Сервер сверяет её со своей и предупреждает,
если расширение старше: несовпадение проявляется иначе — метод отвечает пустотой,
и это неотличимо от отсутствия данных.
